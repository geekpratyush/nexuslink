NexusLink

One desktop workbench for the protocols an enterprise actually runs on — REST, SQL, MongoDB, Redis, Kafka, MQTT, RabbitMQ, JMS, IBM MQ, Solace, SQS, Pub/Sub, Service Bus, S3, Azure Blob, GCS, SFTP, FTP, LDAP, SNMP, SSH, gRPC, GraphQL, MCP — with one credential vault, one set of environment variables and one request history across all of them.

Offline-first: no account, no telemetry, no cloud dependency. It runs on an air-gapped network.

Install

Download the launcher for your platform, put it anywhere, and run it. On the first run it fetches the application from your organisation's repository and caches it; every run after that starts from the local copy, offline. You need Java 21 or newer — nothing else.

nexuslink.shLinux and macOS nexuslink.batWindows — command prompt or double-click nexuslink.ps1Windows — PowerShell (the .bat calls this)

On Windows keep nexuslink.bat and nexuslink.ps1 next to each other — the batch file hands over to the PowerShell script. On Linux and macOS, make it executable first: chmod +x nexuslink.sh.

First run

# Linux / macOS
export NEXUSLINK_REPO_URL=https://artifactory.corp/artifactory/libs-release-local
./nexuslink.sh

# Windows
set NEXUSLINK_REPO_URL=https://artifactory.corp/artifactory/libs-release-local
nexuslink.bat

Ask whoever publishes NexusLink in your organisation for the repository URL. If they ship a ~/.nexuslink/bootstrap.conf (or %USERPROFILE%\.nexuslink\bootstrap.conf) with the URL and credentials already in it, you just run the script.

Every option

Run nexuslink --help to see this list from the script itself.

OptionWhat it does
(none)Run. Downloads only if this version is not already cached.
--localRun the build installed in ~/.m2 by publish.sh — no repository needed.
--offlineNever touch the network. Runs the newest cached build, or says there is none.
--version <v>Run a specific version (RELEASE, LATEST, or e.g. 1.2.0).
--repo <url>Use this repository for one run.
--updateDownload this version again, replacing the cached copy.
--freshClear the cache first, then download and run. Use when a build looks wrong.
--listShow what is cached, with sizes.
--cleanDelete every cached build. Add --version to delete just one.
--wherePrint the jar that would run, and exit.
--helpThe full usage text.

Publishing it (for whoever maintains the build)

One script does the right thing wherever it runs — a developer machine or a CI agent:

./dist/publish.sh                 # build, install to ~/.m2, and deploy if a repository is configured
./dist/publish.sh --local         # local only
./dist/publish.sh --deploy        # require a deploy; fail if no repository is configured
./dist/publish.sh --version 1.2.0 # set the release version first

It always installs to ~/.m2 first — that is what makes nexuslink.sh --local work, and in CI it proves the artifact builds before anything is published. Credentials live in ~/.m2/settings.xml under a <server> id, never on the command line, which is also how a CI agent supplies them.

What is inside

HTTP & APIs

REST with collections and a runner, WebSocket, SSE, GraphQL, gRPC. Enterprise auth built in: OAuth 2.0 with PKCE, AWS SigV4, Digest, HMAC, NTLM, mTLS.

Databases

A JDBC workbench that generates the SQL your engine actually accepts, plus MongoDB with a Compass-class tree view, a mongosh-style shell, change streams and GridFS. Redis with a console that sends anything the server supports.

Messaging

Kafka with headers, tombstones, Avro decoding, consumer-group administration and replay. MQTT, RabbitMQ, JMS, IBM MQ, Solace, SQS/SNS, Pub/Sub, Service Bus.

Files & directories

A two-pane commander over SFTP, FTP, S3, Azure Blob, GCS and MongoDB GridFS — with a transfer queue, directory compare and checksums. LDAP, SNMP and an SSH terminal.

One workbench

One encrypted vault, one set of ${VAR} environments, one searchable history, and code generation — shared by every protocol rather than per-tool.

Safe by default

Credentials are never displayed in the clear, destructive statements are previewed and confirmed, and bulk writes count what they would touch before they run.

If something goes wrong

MessageWhat it means
set NEXUSLINK_REPO_URL…The launcher does not know where to fetch from. Export the variable, or ask for the bootstrap.conf.
checksum mismatchWhat arrived does not match the repository — usually a proxy interfering. Retry; if it persists, tell whoever maintains the repository. Nothing is cached.
nothing cached … --offlineThis machine has never run online. Run once with network access first.
Java N found, but … needs 21Install a newer JDK, or point JAVA_HOME at one you have.
Error in glXCreateNewContextNot an error. JavaFX could not get a hardware graphics context and fell back to software rendering; the app runs normally.
